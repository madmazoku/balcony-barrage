# Balcony Barrage
Мультяшная 2D-аркада для Windows и Android. Игрок двигает Гаечку, сбивает миньонов на шариках, сохраняет самодельную броню и разрушает балкон под Толстопузом.

## Текущее состояние
Фаза 1 принята и опубликована в PR #1. Фаза 2 принята владельцем после ограничения угла гаек. Версия 0.2.0 (AI-2). Следующий этап — фаза 3, геймпад и касания. Теперь F5 запускает полный раунд на подписанных фигурах.

## Открытие и проверки
Движок Godot 4.7.2, GDScript, GL Compatibility. Локальная установка G:/Git/Godot/Godot_v4.7.2-stable_win64.exe. В менеджере проектов импортировать project.godot из этой папки.
Из PowerShell выполнить последовательно:
```powershell
& 'G:/Git/Godot/Godot_v4.7.2-stable_win64_console.exe' --headless --path 'G:/Git/balcony-barrage' --editor --import
& 'G:/Git/Godot/Godot_v4.7.2-stable_win64_console.exe' --headless --path 'G:/Git/balcony-barrage' --script res://tools/validate_foundation.gd
```
На другом компьютере заменить пути. Импорт должен завершиться без ошибок, проверка должна напечатать FOUNDATION_OK и вернуть код 0.

## Настройки и оформление
config/gameplay.tres содержит исходные числа для проверки концепции, их можно редактировать в Inspector. Это пробные значения, баланс будет принят в фазе 2.
config/presentation.tres выбирает весь пакет оформления одной ссылкой. assets/packs/prototype/pack.tres — начальная палитра фигур, подписей и шариков. Полный порядок замены, категории и контракт ресурсов описаны в docs/ASSET_PACKS.md. Сцена прототипа уже использует этот выбор. Альтернативный тестовый пакет assets/packs/prototype_alt/pack.tres меняет подписи и палитру. Чтобы выбрать его, заменить путь ExtResource в config/presentation.tres и перезапустить игру. Графика и аудио будут приниматься позже.
art/art-lock.json содержит кандидата для будущей визуальной пробы. Принятая модель и хеши появятся после фазы 4.

## Управление и сборки
Клавиатура работает. A/D или стрелки — бег, пробел без направления — вверх, с направлением — вбок. Одно нажатие — один болт. R — повтор текущего сценария, P или Escape — пауза. Сверху выбор коротких проверочных ситуаций и переключатель мебели в финале. При переключении мебели без рестарта текущая волна сохраняется. Геймпад и касания входят в фазу 3.
Windows и Android экспортируются из одного проекта в фазе 7. Экспортные шаблоны, Android SDK и ключ подписи проверяются тогда. Секреты в Git не добавлять.

## Продолжение работы
Новый агент начинает с AGENTS.md и docs/ROADMAP.md. Правила боя — docs/GAME_DESIGN.md, утилиты — docs/TOOLS.md. После каждой принятой фазы используется AI-N-ветка, PR в master и merge на GitHub по локальному навыку add-to-master.
Генерированные принятые игровые ресурсы включаются в Git. Кеш, сборки, модели и черновики исключаются. Рабочие релизы пока предназначены для частного тестирования.

## Приёмка фазы 2
1. Открыть project.godot и нажать F5. Попробовать полный раунд, победить, затем повторить.
2. Выбрать «Две цели на линии» — болт снимает только один шарик у ближайшего.
3. «Последний шарик у земли» — снять шарик до посадки или дождаться посадки и выбить танка вбок.
4. «Захват + гайка» — потеря брони за один контакт, короткая защита. Повторный контакт без брони приводит к поражению.
5. «Пустой мешок / босс» — попасть с упреждением. Опора ломается только после прыжка и приземления. После пяти стадий победа.
6. Сравнить финал с мебелью и без, решить, оставить ли её. Переключатель доступен и в полном раунде.
7. Переключить presentation.tres на prototype_alt, перезапустить и проверить смену имён и оформления при тех же правилах.

Автоматические проверки после импорта:
```powershell
& 'G:/Git/Godot/Godot_v4.7.2-stable_win64_console.exe' --headless --path 'G:/Git/balcony-barrage' --script res://tools/test_round.gd
```
Ожидается ROUND_TESTS_OK. Проверяет кулдаун, первое попадание, оба вида падения, захват, защиту от двойного урона, победу и поражение, мебель, воспроизводимость, реальный ввод и перезапуск сцены.

Текущие ограничения: оформление статичное, звука и сохранения рекорда ещё нет. Волна из 12 врагов короткая, ориентир 2–4 минуты будет подбираться в фазе 6. Финальное падение босса пока показано переносом фигуры к земле. Физические телефон и геймпад ещё не проверялись.

Метатели целятся в Гаечку в пределах конуса вниз. Параметр nut_max_angle_degrees в config/gameplay.tres задаёт максимальное отклонение от вертикали в каждую сторону, исходно 35 градусов. Если Гаечка дальше сбоку, направление ограничивается краем конуса. Значение 0 даёт бросок строго вниз, допустимы значения до 80 градусов.

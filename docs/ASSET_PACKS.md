# Пакеты оформления
config/presentation.tres — единственная точка выбора. Пакет загружается при запуске сцены, его валидация происходит до начала раунда. Каждый пакет явно описывает свои ресурсы, скрытых fallback нет.

## Категории и контракт static
| Поле | Содержимое |
|---|---|
| characters | player, boss, boss_defeated, normal, tank, thrower; player_right/left/up; armor_0_right и аналогичные 9 слоёв |
| character_variants | массивы Texture2D для normal, tank, thrower; текущие базовая, тёплая и тёмная палитры |
| environment | background, ground, balcony_0 ... balcony_5 |
| effects | crossbow и crossbow_right/left/up, bolt, nut, sack, furniture, rope, armor_0/1/2 |
| balloon_sprites | отдельные Texture2D для каждого цвета; порядок соответствует balloon_palette |
| ui | дополнительные UI-ресурсы при их наличии; сейчас используются стандартные Control и цвета пакета |
| sfx, music | аудио; audio_mode=silent явно объявляет отсутствие в статичной версии |
| display_names, colors | подписи ролей и палитра; у static также hud_panel, result_panel, touch_boundary |

Текущая реализация поддерживает readiness=prototype и static. Animated потребует расширения контракта в фазе 5.
Все foreground PNG имеют прозрачность. Полностью прозрачный balcony_5 обозначает окончательное обрушение.

## Привязки
Кадры Гаечки, её оружия и брони имеют общий холст 768x896. player_anchor=(384,872) — точка опоры ног. player_body_height=495 определяет масштаб относительно высоты игрового хитбокса.
При подготовке разные позы нормализованы по опоре и масштабу головы. Арбалет и каждая деталь брони включаются независимо. Предметы effects/armor_0...2 также доступны в обрезанном виде для будущего отлёта.
balcony_draw_height задаёт только высоту картинки балкона. Пять визуальных ступеней отображаются пропорционально числу ступеней здоровья босса из gameplay.
Игровая геометрия, HP, скорости, тайминги, вероятность и урон находятся в gameplay.tres. Изменения спрайтов не должны менять эти правила.

## Подготовка и происхождение
Весь статичный набор rescue_rangers получен через FLUX.2 Klein 9B FP8 с общими параметрами из art-lock.json. Цветовые варианты, зеркалирование, удаление фона, crop, масштабирование и alpha-композиция выполняются детерминированно из сгенерированных пикселей. Рисованные накладки оружия запрещены.
Исходники и производные слои для повторной подготовки — art/sources/rescue_rangers. Небольшие speckle-компоненты отделённой гайки у носа метателя убраны при вырезке по связанному компоненту.
art/build-static-pack.json содержит входы для существующей утилиты Gemini/scripts/sprite_assets.py build-pack. Файл asset-preparation.json описывает преобразования, provenance хранит исходные спецификации, checksums.json — итоговые PNG.
Хранить .png.import с mipmaps/generate=true, основной CanvasItem использует линейную фильтрацию с mipmaps.

## Проверки
tools/test_asset_pack.gd проверяет все нужные слоты, прозрачность, неверные пакеты и воспроизводимость боя при смене static ↔ prototype через реальную сцену.
tools/capture_pack.gd сохраняет воспроизводимый кадр для проверки направлений и состояний брони.
Технические картинки из art/drafts и исторические кандидаты не являются fallback для runtime.

## Балкон и финальный босс
Все стадии балкона имеют единый кадр 985x250, balcony_draw_height=125; исходные видимые 200 пикселей продолжают отображаться высотой 100. Верхние 87 строк исходного настила не изменяются до финального обрушения. Подпорки заменяются сгенерированными обломками, обшивка берётся из последовательных масочных изменений только ниже настила. Все crop, позиции и порядок перечислены в balcony_preparation манифеста; это данные подготовки оформления, не параметры боя.
Во время финального падения перемещается characters/boss, после касания земли используется отдельный обязательный characters/boss_defeated и открывается экран победы. Покадровая поза падения относится к фазе 5; само перемещение с ускорением уже реализовано в фазе 4 по замечанию владельца.

## Боковая привязка арбалета
weapon_transforms в art/build-static-pack.json задаёт подготовку уже сгенерированного оружия. У правой позы точка anchor=(500,645) на холсте 768x896 совмещает рукоять с кистью; левая зеркалится из готового правого слоя. Прежняя anchor=(484,514) ошибочно помещала оружие на уровне головы. Вертикальная поза и все слои персонажа остаются прежними. Значения также сохранены в asset-preparation.json; существующая утилита sprite_assets.py читает их из манифеста.

## Крепление верёвок шариков
balloon_rope_anchor — нормализованная точка крепления в изображении шарика, для текущего пакета (0.5,0.98), нижний хвостик. Манифест подготовки хранит это поле, утилита переносит его в pack.tres и asset-preparation.json. Представление масштабирует точку вместе со спрайтом и начинает верёвку от неё, включая крайние наклонные верёвки танка. Игровой центр, хитбоксы, шаг шариков и случайные цвета не сдвигаются. У пакета фигур линия начинается на нижней границе круга.

## Временные эффекты первой группы фазы 5
У пакета явно заданы feedback: FeedbackConfig и balloon_pop_frames: Dictionary[String,Array], ключ — индекс цвета. Наличие одной половины без второй не проходит валидацию. Без feedback исходный пакет фигур продолжает работать как раньше; скрытого поиска картинок в других пакетах нет. Слово static пока относится к базовым кадрам персонажей, не к отсутствию временных эффектов.
FeedbackConfig содержит enabled, время/наклон/сжатие выстрела, длительность кадра/размер лопания, время/скорость/гравитацию/вращение/масштаб полёта брони. Все значения сериализованы в feedback.tres и в манифесте подготовки. RoundFeedback владеет только временем и декоративными траекториями. Кулдаун, здоровье и попадания остаются в RoundModel.
Лопание использует фиксированный холст 256x256, четыре последовательных crop одного сгенерированного листа, четыре производных цвета по прежнему HSV-преобразованию. Мелкие обрывки не обрезать заново по bbox каждого кадра: это нарушит масштаб распада. Убран только зелёный фон и рамка листа. Mipmaps включены.
Отдача преобразует все слои Гаечки совместно вокруг точки ног, поэтому принятая привязка арбалета сохраняется. Начало полёта брони вычисляется из alpha-границ её текущего слоя и той же визуальной трансформации. При краже свободный полёт не создаётся: украденная деталь показана у убегающего миньона. Изменения визуализации не меняют центры коллизий.

## Группа 2: позы врагов и перенос брони
enemy_action_frames хранит пять явных действий: thrower_windup, thrower_release, normal_capture, tank_capture, thrower_capture; у каждого три палитры в порядке character_variants. thrower_capture явно использует те же текстуры, что release; tank_capture использует полный исходный кадр принятого танка и движение корпуса. Это данные пакета, а не скрытый fallback.
Каждый новый кадр имеет холст 512x512. enemy_frame_bounds задаёт нормализованный bbox исходной нейтральной позы каждого типа. Масштаб и центр тела рассчитываются относительно этого bbox; не обрезать вытянутую руку заново по контуру кадра. Приёмке подлежат совмещение головы/ног и читаемость замаха.
FeedbackConfig.enemy_actions_enabled включает контракт действий. Включённый пакет обязан содержать все пять действий, палитры и корректные bounds; prototype по-прежнему обходится без них. release_seconds, capture_seconds, armor_transfer_seconds, windup_tilt_degrees, capture_tilt_degrees, capture_reach_fraction, carry_offset и carry_size — только визуальные данные.
Бросок показывает release только при настоящем событии создания гайки. Посадка и сбитый враг отменяют замах. Захват сначала направлен к игроку, затем изображение догоняет уже убегающего врага. Бой не ждёт анимацию. Деталь берётся из текущей позы Гаечки, переходит к носителю и без дублирования остаётся у него после окончания эффекта. Пауза и перезапуск обрабатывают все стадии.
Для новых поз использованы масочные изменения исходных персонажей FLUX.2 с denoise 0.95; локальная ретушь замаха 0.65. Убраны фоновые артефакты, скорректирован цвет сгенерированного участка руки/жилета и alpha. Модель/hash/sampler/steps/guidance прежние. Новых рисованных деталей нет; исходные спецификации и подготовленные RGBA сохранены.

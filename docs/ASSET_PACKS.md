# Пакеты оформления
config/presentation.tres — единственная точка выбора. Пакет загружается при запуске сцены, его валидация происходит до начала раунда. Каждый пакет явно описывает свои ресурсы, скрытых fallback нет.

## Категории и контракт static
| Поле | Содержимое |
|---|---|
| characters | player, boss, boss_defeated, normal, tank, thrower; player_right/left/up; armor_0_right и аналогичные 9 слоёв |
| character_variants | массивы Texture2D для normal, tank, thrower; текущие базовая, тёплая и тёмная палитры |
| environment | background, ground, balcony_0 ... balcony_5 |
| effects | crossbow и crossbow_right/left/up, bolt, nut, sack, furniture, rope, armor_0/1/2 |
| balloon_sprites | отдельные Texture2D для каждого цвета; порядок соответствует balloon_palette |
| ui | дополнительные UI-ресурсы при их наличии; сейчас используются стандартные Control и цвета пакета |
| sfx, music | аудио; audio_mode=silent явно объявляет отсутствие в статичной версии |
| display_names, colors | подписи ролей и палитра; у static также hud_panel, result_panel, touch_boundary |

Текущая реализация поддерживает readiness=prototype и static. Animated потребует расширения контракта в фазе 5.
Все foreground PNG имеют прозрачность. Полностью прозрачный balcony_5 обозначает окончательное обрушение.

## Привязки
Кадры Гаечки, её оружия и брони имеют общий холст 768x896. player_anchor=(384,872) — точка опоры ног. player_body_height=495 определяет масштаб относительно высоты игрового хитбокса.
При подготовке разные позы нормализованы по опоре и масштабу головы. Арбалет и каждая деталь брони включаются независимо. Предметы effects/armor_0...2 также доступны в обрезанном виде для будущего отлёта.
balcony_draw_height задаёт только высоту картинки балкона. Пять визуальных ступеней отображаются пропорционально числу ступеней здоровья босса из gameplay.
Игровая геометрия, HP, скорости, тайминги, вероятность и урон находятся в gameplay.tres. Изменения спрайтов не должны менять эти правила.

## Подготовка и происхождение
Весь статичный набор rescue_rangers получен через FLUX.2 Klein 9B FP8 с общими параметрами из art-lock.json. Цветовые варианты, зеркалирование, удаление фона, crop, масштабирование и alpha-композиция выполняются детерминированно из сгенерированных пикселей. Рисованные накладки оружия запрещены.
Исходники и производные слои для повторной подготовки — art/sources/rescue_rangers. Небольшие speckle-компоненты отделённой гайки у носа метателя убраны при вырезке по связанному компоненту.
art/build-static-pack.json содержит входы для существующей утилиты Gemini/scripts/sprite_assets.py build-pack. Файл asset-preparation.json описывает преобразования, provenance хранит исходные спецификации, checksums.json — итоговые PNG.
Хранить .png.import с mipmaps/generate=true, основной CanvasItem использует линейную фильтрацию с mipmaps.

## Проверки
tools/test_asset_pack.gd проверяет все нужные слоты, прозрачность, неверные пакеты и воспроизводимость боя при смене static ↔ prototype через реальную сцену.
tools/capture_pack.gd сохраняет воспроизводимый кадр для проверки направлений и состояний брони.
Технические картинки из art/drafts и исторические кандидаты не являются fallback для runtime.

## Балкон и финальный босс
Все стадии балкона имеют единый кадр 985x250, balcony_draw_height=125; исходные видимые 200 пикселей продолжают отображаться высотой 100. Верхние 87 строк исходного настила не изменяются до финального обрушения. Подпорки заменяются сгенерированными обломками, обшивка берётся из последовательных масочных изменений только ниже настила. Все crop, позиции и порядок перечислены в balcony_preparation манифеста; это данные подготовки оформления, не параметры боя.
Во время финального падения перемещается characters/boss, после касания земли используется отдельный обязательный characters/boss_defeated и открывается экран победы. Покадровая поза падения относится к фазе 5; само перемещение с ускорением уже реализовано в фазе 4 по замечанию владельца.

## Боковая привязка арбалета
weapon_transforms в art/build-static-pack.json задаёт подготовку уже сгенерированного оружия. У правой позы точка anchor=(500,645) на холсте 768x896 совмещает рукоять с кистью; левая зеркалится из готового правого слоя. Прежняя anchor=(484,514) ошибочно помещала оружие на уровне головы. Вертикальная поза и все слои персонажа остаются прежними. Значения также сохранены в asset-preparation.json; существующая утилита sprite_assets.py читает их из манифеста.

## Крепление верёвок шариков
balloon_rope_anchor — нормализованная точка крепления в изображении шарика, для текущего пакета (0.5,0.98), нижний хвостик. Манифест подготовки хранит это поле, утилита переносит его в pack.tres и asset-preparation.json. Представление масштабирует точку вместе со спрайтом и начинает верёвку от неё, включая крайние наклонные верёвки танка. Игровой центр, хитбоксы, шаг шариков и случайные цвета не сдвигаются. У пакета фигур линия начинается на нижней границе круга.

## Временные эффекты первой группы фазы 5
У пакета явно заданы feedback: FeedbackConfig и balloon_pop_frames: Dictionary[String,Array], ключ — индекс цвета. Наличие одной половины без второй не проходит валидацию. Без feedback исходный пакет фигур продолжает работать как раньше; скрытого поиска картинок в других пакетах нет. Слово static пока относится к базовым кадрам персонажей, не к отсутствию временных эффектов.
FeedbackConfig содержит enabled, время/наклон/сжатие выстрела, длительность кадра/размер лопания, время/скорость/гравитацию/вращение/масштаб полёта брони. Все значения сериализованы в feedback.tres и в манифесте подготовки. RoundFeedback владеет только временем и декоративными траекториями. Кулдаун, здоровье и попадания остаются в RoundModel.
Лопание использует фиксированный холст 256x256, четыре последовательных crop одного сгенерированного листа, четыре производных цвета по прежнему HSV-преобразованию. Мелкие обрывки не обрезать заново по bbox каждого кадра: это нарушит масштаб распада. Убран только зелёный фон и рамка листа. Mipmaps включены.
Отдача преобразует все слои Гаечки совместно вокруг точки ног, поэтому принятая привязка арбалета сохраняется. Начало полёта брони вычисляется из alpha-границ её текущего слоя и той же визуальной трансформации. При краже свободный полёт не создаётся: украденная деталь показана у убегающего миньона. Изменения визуализации не меняют центры коллизий.

## Группа 2: позы врагов и перенос брони
enemy_action_frames хранит пять явных действий: thrower_windup, thrower_release, normal_capture, tank_capture, thrower_capture; у каждого три палитры в порядке character_variants. thrower_capture явно использует те же текстуры, что release; tank_capture использует полный исходный кадр принятого танка и движение корпуса. Это данные пакета, а не скрытый fallback.
Каждый новый кадр имеет холст 512x512. enemy_frame_bounds задаёт нормализованный bbox исходной нейтральной позы каждого типа. Масштаб и центр тела рассчитываются относительно этого bbox; не обрезать вытянутую руку заново по контуру кадра. Приёмке подлежат совмещение головы/ног и читаемость замаха.
FeedbackConfig.enemy_actions_enabled включает контракт действий. Включённый пакет обязан содержать все пять действий, палитры и корректные bounds; prototype по-прежнему обходится без них. release_seconds, capture_seconds, armor_transfer_seconds, windup_tilt_degrees, capture_tilt_degrees, capture_reach_fraction, carry_offset и carry_size — только визуальные данные.
Бросок показывает release только при настоящем событии создания гайки. Посадка и сбитый враг отменяют замах. Захват сначала направлен к игроку, затем изображение догоняет уже убегающего врага. Бой не ждёт анимацию. Деталь берётся из текущей позы Гаечки, переходит к носителю и без дублирования остаётся у него после окончания эффекта. Пауза и перезапуск обрабатывают все стадии.
Для новых поз использованы масочные изменения исходных персонажей FLUX.2 с denoise 0.95; локальная ретушь замаха 0.65. Убраны фоновые артефакты, скорректирован цвет сгенерированного участка руки/жилета и alpha. Модель/hash/sampler/steps/guidance прежние. Новых рисованных деталей нет; исходные спецификации и подготовленные RGBA сохранены.

## Группа 3: бег (принята в 0.9.0; первоначальная подготовка)
locomotion: MotionConfig и run_frames: Dictionary[String,Array] принадлежат пакету. player_right/left/up содержат последовательности Texture2D общего холста 768x896; normal_0/1/2, tank_0/1/2, thrower_0/1/2 — последовательности для каждой палитры на общем холсте 512x512. Все слоты обязательны при наличии locomotion, чужие кадры не подставляются. Нейтральные кадры явно включены в последовательность; танк разделяет полный нейтральный кадр с tank_capture. Для врагов остаётся тот же enemy_frame_bounds.
Боковой цикл Гаечки содержит две новые позы шага и принятый нейтральный кадр между ними; левый зеркалится. Вверх — короткая последовательность новой позы и прежней нейтральной. Каждый тип миньона чередует принятую форму и сгенерированный шаг. Это начальные короткие циклы, не плавная многокадровая анимация. Перед сменой стиля или расширением кадров нужна приёмка.
RoundMotion измеряет изменение игровых координат после шага модели. stride_pixels и bob_pixels для четырёх ролей находятся в motion.tres, исходные значения — locomotion.settings манифеста. При упоре в край, остановке и окончании боя ноги не продолжают бег. Пауза сохраняет кадр, перезапуск очищает состояние; удалённые враги удаляются из реестра. Замах/захват имеют приоритет над циклом ног. При окончании захвата возвращается бег, а деталь следует за тем же визуальным положением тела.
Верхние 727 строк боковых кадров и 718 строк верхнего кадра Гаечки копируются из принятой исходной позы. Поэтому голова, руки и точки оружия/брони совпадают побайтно. Масштаб нижней полосы нормализован по прежней опоре ног; данные сохранены в sources. Для метателя стопа из исходного сгенерированного персонажа скомпонована позади поднятой голени; это разрешённая сборка сгенерированных пикселей, без рисования. Ошибочные пробы ног не включены в пакет.
Группа добавляет 20 PNG: пять кадров Гаечки, девять цветных шагов врагов и шесть полных нейтральных кадров обычного/метателя. Всего 95. Прежние 75 сохраняются побайтно; base readiness остаётся static, дополнительные действия и циклы объявлены отдельно.

## Доработка цикла и финалы поражения (2026-11-07)
В enemy_sources поддерживаются extra_sources и sequence; без них остаётся прежний двухкадровый контракт подготовки. Текущая последовательность всех наземных типов — neutral/stride/neutral/opposite, три варианта палитры. У босса отдельный boss_0, одна палитра, enemy_frame_bounds.boss и locomotion.boss_enabled. Бег босса не проигрывается во время его прыжка, падения и результата. Для minion/boss верх копируется из исходника по preserve_upper_source_rows, новые кадры используют общий холст 512x512.
FeedbackConfig.defeat_enabled включает отдельное представление поражения и требует локальные locomotion и позы захвата в том же пакете. Поля defeat_transfer_seconds/min_seconds/max_seconds/offscreen_margin, defeat_launch_velocity/gravity/spin_radians, defeat_carry_offset/angle_degrees и defeat_weapon_drop_seconds/launch_velocity задают только визуальную реакцию. Тип и источник последнего урона передаёт player_defeated из RoundModel, не выводить их из текста причины.
RoundFeedback.defeat хранит снимок слоёв персонажа и визуальную копию захватчика. Она не добавляется в модель и не может наносить урон. Захваченная Гаечка не рисуется на старом месте; исходный захватчик скрывается в пользу одной движущейся копии. Её body и выпавший AtlasTexture арбалета используют принятые сгенерированные пиксели. При уносе weapon=null, отдельный арбалет падает из alpha-границ текущего слоя рук. Бой/счёт заморожены результатом lose, эффекты продолжаются до выхода с экрана, потом видна панель. Prototype и отключённые эффекты сохраняют немедленный исход без этих картинок.
Всего 107 PNG. Бег Гаечки и все прежние 75 PNG сохранены. У танка один ботинок и сдвиг шага подготовлены из существующих сгенерированных деталей; у метателя перекрёстный референс собран alpha-выделением и преобразованием исходных ног и отретуширован той же FLUX.2. Все crop/операции записаны в sources. Не подключать отбракованные сырьевые попытки.

## Группа 4: действия босса
Опциональные boss_actions: BossActionConfig и boss_action_frames: Dictionary[String,Texture2D] включают reach/release/hold/air/land на полном холсте 512x512 с прежним enemy_frame_bounds.boss. Отдельный effects.sack_open обязателен для этого контракта. Нет скрытых замен из другого пакета; при отсутствии всей опции прежнее представление сохраняется.
Настройки в boss_actions.tres: reach_seconds/release_seconds/throw_seconds/landing_seconds, jump_stretch/landing_squash, sack_offset/size/pulse, furniture_hold_offset/lift_offset, swing_fraction/lift_fraction и fall_tilt_degrees. Все координаты предметов нормализованы по boss_size; размеры игрового урона остаются gameplay. При последней части замаха предмет опускается к реальному началу траектории (model.boss), при отпускании отдельного предмета в руках уже нет. Действие выпуска/удар/отпускание привязаны к факту boss_action, не к догадке по тексту события.
Первый предпросмотр группы добавлял 6 PNG (всего 113); после принятой доработки бега итог 118, см. ниже. Новые позы имеют одну палитру босса. Маски, исходные пиксели, регистрация головы/опоры и цепочка уточнений находятся в boss_actions source-рецептах. Вариант hold использует исходную сгенерированную поднятую позу, не отбракованную ретушь галстука. База readiness=static продолжает описывать нейтральные позы; дополнительные действия задаются явно.

## Доработанный цикл босса
boss_0 использует восемь явно перечисленных фаз contact_a/recoil_a/pass_a/lift_a/contact_b/recoil_b/pass_b/lift_b. Все имеют полный холст 512x512 и прежние boss reference bounds. Исходные целые ноги и обувь выделены из уже сгенерированного персонажа; рецепт не рисует новых пикселей, только преобразует и собирает существующие.
MotionConfig.bob_cycles — необязательная частота синуса до abs(): значение 1 даёт два подъёма за цикл, отсутствующая роль сохраняет прежнее значение 2. Текущий boss=1, другие роли не менялись. BossActionConfig.walking_split_fraction задаёт границу верхней позы reach/release/hold и текущих ног при настоящем горизонтальном движении. Оба слоя используют ту же регистрацию; воздушные и посадочные позы не разрезаются. Текущий runtime — 118 PNG; прежние три босса заменены восемью. Старые исходники сохранены как история, а их runtime PNG и .import удалены из активного пакета.

## Принятая группа 5: окружение (0.11.0)
Опциональный ambient: AmbientConfig ссылается на слои только активного пакета. environment содержит ambient_background и ambient_<layer_id>. source_size — исходный холст, layer_rects — нормализованные прямоугольники, periods — секунды, amplitudes — пиксели исходника, turns — число волн по высоте, phases — старт [0,1), segments — число сегментов 2..64. Валидация требует все слои, положительные периоды и согласованные размеры. enabled=false рисует оригинальный background того же пакета. Отсутствующий ambient разрешён для статичных и prototype наборов, чужих ресурсов нет.

RoundAmbient деформирует исходные растровые пиксели гладкой волной, закрепляет оба конца, хранит три постоянных ArrayMesh, не знает модель/RNG. Фон рисуется до пола/HUD/балкона/актёров. Бой может остановить продвижение представления, но фон не влияет на бой. right_top/right_lower разделены у неподвижного карниза. Runtime 122 PNG, на 4 больше принятой 0.10.0; 118 старых побитово сохранены.

## Фаза 6: меню в составе пакета
Обязательный ui.shell_style: ShellStyle задаёт название/подзаголовок игры, цвета panel/border/accent/text/muted/button/dim и размеры panel_width/heading_size/body_size/button_height. У rescue_rangers, prototype и prototype_alt собственные ресурсы shell_style.tres. AssetPack проверяет наличие и положительные размеры до старта. Никаких скрытых подстановок темы из rescue_rangers при выборе prototype.
GameShell создаёт стандартные Control/Theme по этому ресурсу, картинки персонажей и окружения остаются прежними. shared script класса ShellStyle допустим как определение формата. Рецепт build-pack хранит путь shell_style в art/build-static-pack.json, не терять ui при повторной сборке. Пользовательские предпочтения не записываются в ресурс пакета.


## Манифест, выбор и составы сборок (F1)
Обычный запуск GameShell использует config/pack_catalog.json: schema/default_pack/profiles/debug/release/restricted_packs/packs. В packs находятся id, name, description, path, preview, status, release_ready и опциональный migration. Пути оформления/превью принадлежат собственному каталогу. PackCatalog загружает и проверяет выбранный полный AssetPack. config/presentation.tres остаётся прямым выбором для старой QA-сцены/F6; при экспорте его ссылка тоже переписывается в разрешённый default_pack. В меню нет жёсткого списка из двух паков; для третьего добавить ресурс, запись и ID в нужный профиль.
Выбор сохраняется независимо от баланса/рекордов. Переключение заменяет сцену целиком после завершения/сброса текущего раунда; в паузе только сохраняется намерение. Предпочтения движения фона/подсказок/касания применяются к новому паку без мутации его ресурсов. При недоступном сохранённом ID используется default_pack установленного манифеста.
forest_glade содержит собственные Texture2D, настройки feedback/motion/boss_actions/ambient/shell_style. Ни один .tres не ссылается на rescue_rangers. Инверсия RGB, alpha без изменений; палитра парашютов инвертирована соответственно картинкам. migration.json хранит исходные и текущие placeholder SHA, категорию, размер и независимые placeholder/accepted. Техническая validation_errors()==[] означает полноту слотов, а не приёмку оригинального лесного оформления.
Release экспорт требует ID в profiles.release, status=ready/release_ready=true, отсутствия ID в restricted_packs, при наличии migration — полного принятого списка всех PNG без заглушек и release_ready=true. Временный проект физически лишён исключённых каталогов; проверка .tres не разрешает внешние зависимости между пакетами. После экспорта проверяются каталоги и манифест непосредственно внутри ресурспака артефакта. Debug содержит оба текущих пакета; release сейчас намеренно пуст и блокируется.


## Размер снаряда в оформлении
Опциональный AssetPack.projectile_draw_sizes: Dictionary[String, Vector2] задаёт только размер рисования. Ключ bolt у лесного пака равен (12,12), поэтому сгенерированный камешек не растягивается в болт. Без ключа сохраняется прежний вид и размер. Валидация запрещает неположительные/нечисловые размеры. Скорость, коллизия, точка создания, урон и кулдаун остаются в GameplayConfig/RoundModel.


AssetPack.projectile_visual — опциональный ProjectileVisualConfig активного пака; отсутствие сохраняет прежний рендер. trail_length/samples/tail_scale/opacity/tint и glint_period/strength/power/tint задают только вид снаряда. enabled=false выключает эффект. Периоды/числа конечные, сэмплы 2..32; настройки проверяются до запуска. Trail использует исходный PNG effects.bolt, отдельные рисованные объекты не добавлены.


## Пропорции персонажа отдельно от коллизии
AssetPack.preserve_actor_aspect — опциональный PackedStringArray ролей normal/tank/thrower/boss. actor_draw_size(role, collision_size) сохраняет collision_size.y и выводит ширину по characters[role] (нейтральный tight PNG), а не по текущей расширенной позе. Одинаково применяется в _sprite_body и _draw_registered, включая бег/действия/носителя при поражении. Без флага старый вид неизменен. Валидация требует допустимую роль и собственную непустую текстуру. Столкновения/точки спавна/баланс всё ещё принадлежат GameplayConfig/RoundModel. Включено для лесной белки и кабанчика.


Кабанчик F4: 12 PNG роли tank заменены собственными ресурсами; tank_capture явно одновременно neutral/capture, в run_frames нейтральная фаза ссылается на тот же полный холст. Тесные tank/base/warm/dark используются статично через character_variants. preserve_actor_aspect теперь для tank/thrower; хитбоксы не меняются.

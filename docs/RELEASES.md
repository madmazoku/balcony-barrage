# Автоматические релизы по тегам (AI-13)
Статус 2026-11-09: реализовано по прямому поручению владельца сделать Actions-релизы и поставить первый тег. Первый выпуск — 0.13.0-preview. Это техническая часть фазы 7, а не приёмка звука/баланса или физических устройств. Постоянный ключ Android создан и секреты настроены с отдельного разрешения владельца.

## Что работает сейчас
.github/workflows/web-pages.yml автоматически запускает проверки и Web-экспорт для PR в master. После приёмки и merge push в master повторяет проверки, экспортирует и разворачивает Pages. Вручную ничего не собирается и workflow_dispatch отсутствует. Feature-ветки не публикуются. Главная страница: https://madmazoku.github.io/balcony-barrage/ .

## Результат workflow
Push одного нового тега, например 1.2.3 или 1.2.3-demo, запускает сборку именно коммита тега:
- balcony-barrage-<tag>-windows-x86_64.zip — исполняемая игра и нужные файлы, без редактора.
- balcony-barrage-<tag>-android.apk — устанавливаемый APK с постоянной подписью.
- balcony-barrage-<tag>-web.zip — полная Web-сборка для HTTP/HTTPS сервера.
- SHA256SUMS.txt и метаданные с тегом, полным commit SHA, версией Godot и идентификатором сборки.
GitHub Release носит имя тега, содержит все три готовых файла, контрольные суммы, описание и ссылку «Играть». AAB для Google Play не заменяет устанавливаемый APK; добавляется только при отдельной задаче.

Формат: x.y.z или x.y.z-short_desc, где short_desc строго соответствует [a-zA-Z0-9_-]+: одна или несколько латинских букв любого регистра, цифр, дефисов и подчёркиваний. Например 1.2.3-Alpha_01--test; числовой суффикс 01 также допустим. Это явно заданный владельцем формат от 2026-11-09, а не строгий SemVer для суффикса. Дополнительного ограничения 80 символами нет. Точки, пробелы, разделители путей и прочие символы в суффиксе запрещены. Номера x/y/z — ASCII-цифры без ведущих нулей, каждый не больше 65535 для Windows. Валидировать до сборки, не использовать необработанный тег как shell-команду или путь. Суффикс означает предварительный выпуск (prerelease), не делать его автоматически последней стабильной версией. Тег без суффикса — стабильный выпуск. Отклонять пустой суффикс.

## Порядок и контроль приёмки
1. Триггер push.tags, фильтр плюс строгая проверка формата. Полная история для проверки ancestry.
2. Коммит тега должен принадлежать принятому master. Теги feature-веток не обходят приёмку. Наличие коммита в master — технический критерий действующего процесса приёмки; не заменять его простым совпадением номера версии.
3. Проверки и импорт проходят до публикации. Использовать общую проверенную процедуру, не плодить две расходящиеся копии установки Godot/проверок.
4. Общая установка .github/actions/setup-godot/action.yml и tools/release.py. Godot 4.7.2 и export templates той же версии, проверка официальных контрольных сумм. Версию конкретной сборки брать из тега без изменения исходного коммита: в рабочей копии CI задать application/config/version. Полная строка тега отображается в игре, числовые поля Windows получают x.y.z, Android version/name — полный тег, version/code — возрастающий номер сборки.
5. Собрать Windows, Android и Web. Дождаться всех трёх, проверить состав и хеши, затем создавать Release. Не публиковать молча неполный набор.
6. Повторный запуск для того же тега должен безопасно продолжать незавершённый выпуск, а не создавать дубликат. Не перемещать тег и не заменять готовые файлы другим содержимым без решения владельца.
7. Публикацию выполнять разрешёнными contents:write, pages:write, id-token:write только в соответствующих заданиях. Доступ на запись и секреты не выдавать непроверенным PR. Первый тег явно поручен владельцем. Дальнейшие игровые изменения публикуются после обычной приёмки.

## Pages: текущая и конкретные версии
Сохранить нынешнюю главную страницу как последнюю принятую сборку master. Для тегов добавить /releases/<tag>/ и список доступных версий со ссылками на скачивание. Старый тег не должен откатывать главную страницу. Обновление master не должно удалять ранее размещённые версии.
У Pages один публикуемый сайт: архив версий нужно собирать целиком при каждом развёртывании. Источник архивов — опубликованные web.zip из GitHub Releases, с проверкой метаданных/хешей; данные не зависимы от временного кеша runner. Новая версия включается в тот же пакет сайта. Задание deploy для master и тегов использует одну очередь balcony-pages-site, получает свежий master после получения блокировки и восстанавливает каталог из опубликованных релизов, чтобы не затирать версии и не откатывать главную. Путь каждой версии содержит полный тег, нельзя использовать только x.y.z, теряя суффиксы.
Опубликованный сайт ограничен 1 ГБ. Контролировать размер до deploy; при превышении останавливать публикацию с понятной причиной. Не удалять старые версии автоматически без согласованной политики хранения. Вложения Releases остаются доступными независимо от списка версий, размещённых на Pages.

## Android и подпись
CI устанавливает Temurin JDK 17, Android build-tools 36.0.0/platform 36 и шаблоны Godot 4.7.2, без локального Visual Studio. Для устанавливаемых обновлений один постоянный keystore и package ID. Ключ, alias и пароли — в GitHub Secrets, не в репозитории, артефактах и логах. Владелец разрешил новый ключ; резервная копия C:/Users/madma/.codex/secrets/balcony-barrage защищена ACL пользователя/SYSTEM и не входит в Git. Хранить release.p12 вместе с credentials.json в защищённой резервной копии, содержимое не публиковать. Секреты репозитория: ANDROID_KEYSTORE_BASE64, ANDROID_KEYSTORE_PASSWORD, ANDROID_KEY_ALIAS. В CI ключ временно восстанавливается в RUNNER_TEMP, значения передаются Godot через переменные окружения, файл удаляется даже при ошибке. Случайный новый debug-ключ на каждом запуске не подходит для обновления ранее установленной игры.

## Приёмка автоматизации
На принятом коммите проверить правильный тег и отказ неправильному/непринятому. Проверить три вложения и их SHA256, имя/версию в каждой сборке, Windows без редактора, установку и обновление APK тем же ключом, Web по ссылке версии. Проверить повторный запуск, порядок стабильных/prerelease выпусков, сохранение старой версии после новой публикации master и отсутствие отката главной при старом теге. Физическая проверка телефона — владельцем, не заменяется успешным экспортом.

## Команды и повторный запуск
После приёмки/merge: git tag -a 0.13.0-preview -m "First downloadable preview" и git push origin 0.13.0-preview. Никогда не переставлять опубликованный тег. GitHub Actions по тегу собирает все три платформы, создаёт черновик и заполняет его только после проверок; затем публикует prerelease и Pages. При повторном запуске готовые вложения не перезаписываются. Незавершённый черновик можно дозаполнить тем же workflow. Если опубликованные вложения вручную удалены/испорчены, восстановление требует отдельного решения, тихой подмены нет.
PR собирает те же платформы с отдельным временным ключом, без доступа к настоящим секретам; пакеты доступны в game-builds artifact на 7 дней. Master проверяет/обновляет главную и каталог без создания Release. No workflow_dispatch. Текущие подготовительные проверки и ограничения записаны в ROADMAP.
